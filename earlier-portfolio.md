## 🧠 STAR Method Reflections

### 1. Reflection on coding my CV in Markdown

**Situation**  
I needed to present my professional CV inside a GitHub portfolio using only Markdown syntax, without a word processor.

**Task**  
Convert my traditional PDF CV into a clean, readable Markdown document while keeping its structure, headings, lists, and links.

**Action**  
- Used GitHub Flavoured Markdown (GFM)
- Created headings (`#`, `##`, `###`) for each section
- Used bullet lists for skills and goals, and tables for education and references
- Added links for my email, LinkedIn, and GitHub

**Result**  
I now have a version-controlled CV that is easy to update, share, and display on GitHub Pages. I learned that Markdown is a powerful tool for technical documentation and portfolio building.

### 3. Reflection on using GitHub Pages

**Situation**  
I had to deploy my digital portfolio as a live website using GitHub Pages.

**Task**  
Configure my GitHub repository to serve my Markdown files as a website that anyone can open through a public link.

**Action**  
- Used my repository `ElamMtshwane.github.io`
- Went to Settings → Pages and set the source to *Deploy from a branch*, with the branch `main` and the folder `/ (root)`
- Used `index.md` as the homepage and `CV.md` as a second page
- Committed my files, then waited 1–2 minutes for the site to deploy
- Opened the live link to check that the pages and links worked

**Result**  
My portfolio is live at [https://elamm2.github.io/ElamMtshwane.github.io/](https://elamm2.github.io/ElamMtshwane.github.io/). I learned how static site hosting works, that a repository link and a GitHub Pages link are not the same thing, and why GitHub Pages is a good way for students to showcase their work.
